## v2.4.2 — 录音实时出字改用常驻识别

本版只改「麦克风录制」那条链路：逐段出字不再每段重新加载模型。推理质量、
模型选择、文件转录与打包方式与 v2.4.1 相同。

### ⚡ 录音免重复加载

- 旧路径：每说完一句就 spawn 一次 `crispasr.exe`，模型每次重新上显存，
  固定开销占实时出字延迟 ~90%（whisper base ≈0.6s、qwen3 Q8 ≈2.35s/段）。
- 现在：录音开始时在后台起一个常驻 `crispasr --server`（**只绑 127.0.0.1**、
  端口动态分配），模型只加载一次，每段音频用 `/v1/audio/transcriptions`
  复用同一份模型。
- 实测（GTX 1660 SUPER / 核心 0.8.54 CUDA / 11 秒英文语音）：

  | 路径 | 耗时 |
  |---|---|
  | 常驻服务 · Whisper Base 温请求 | **0.17-0.23 秒/段** |
  | 常驻服务 · Qwen3 1.7B Q8 温请求 | 1.12 秒（11s 音频；3s 段约 0.3-0.5s） |
  | 冷启动（模型首次上显存） | Base 0.8s / Qwen3 17.2s —— 只在开录时付一次 |

### 🧠 显存让位

- 开录即预热常驻服务；**停录后宽限 20 秒**再停（收尾段还要上传，立即杀会让最后一句
  重新冷启动）；换模型、开始批量转录前立即停——避免常驻模型与批量任务的一次性进程
  各占一份显存（4GB 卡会 OOM）。批量任务进行中开录不会预热，等队列空闲后按需起。

### 🧹 不再产垃圾

- 实时分段不再往 `subtitles/` 每段落一个字幕文件（旧路径会）；时间轴本来就由录音时钟
  给出，分段上传也不必先过 ffmpeg 抽音轨（crispasr 自己解 webm/ogg）。

### 🔁 自动回退

- 核心不带 `--server`（旧版）或常驻服务起不来时：只尝试一次，之后退回「每段启动一次」的
  旧路径——结果不变，只是出字延迟回到秒级，日志会留一行说明。

### 🗑️ 文档清理

- 删除 `requirements-gpu.txt`（只剩「已删除」说明的空壳，内容在 `requirements.txt` 尾部注释已有）。
- 删除 `docs/upstream-feature-request-crispasr.md`：这份上游 feature request 草稿的前提
  （「crispasr 没有 server 模式、无稳定 C ABI」）经 0.8.54 实测证伪——`--server`、
  `--ws-port`、`--server-workers`、`include/crispasr.h` 上游都有。

### 验证

- 新增 22 例实时分段回归（切句、请求字段、服务失败回退、启动失败不自锁死、宽限释放、
  编排层不落产物）；本机全套 186 例。
- 真机端到端：`set_recording(True)` → 逐段 `transcribe(realtime=1)` → 停录宽限释放，
  Whisper Base 单段 0.19-0.23s，文本正常、无字幕文件产出。

### 升级说明

- onedir 覆盖安装即可；onefile 解压替换 exe。`settings.json`、模型、队列归档沿用。
- 与 v2.4.1 相同：首次使用 GPU 核心时会自动下载上游最新 CrispASR。
