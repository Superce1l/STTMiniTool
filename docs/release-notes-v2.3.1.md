## v2.3.1 — 双开稳定 + 长视频不再误报「请求超时」

修掉反馈 #4 / #5 / #6 指向的同一组问题：长素材在「同时开两个实例」时被误判为请求超时，界面报错、后端还在跑，最后拿不到产物。安装包为目录版（EXE + `_internal/`），首次运行按需下载模型。

### ⏱️ 长视频不再误报「请求超时」
- 前端原先对「上传 + 转录」硬限 **30 分钟**。53 分钟素材单跑约 25 分钟，两个实例并行时被 GPU 争用拖过这条线 → 前端 abort、后端仍在转录，界面显示「请求超时」且结果无人接收。
- 改为**不设固定分钟数**（只留 6 小时兜底），控制面交给 **SSE 进度 + 取消按钮**。

### 🔌 断开即停
- 服务端在转录期间每秒探测连接（`select` + `MSG_PEEK`），浏览器 abort／关标签页／关窗后**1 秒内取消转录**并写日志，不再空烧 GPU 跑完整档。

### 🛡️ 单实例守卫
- 第二个实例不再静默双开：弹窗三选一 ——「打开已有窗口（默认）／仍要并行／退出」。
- 并行时日志按 PID 分文件（`app-YYYYMM-pidN.log`），启动横幅记录 pid／端口／日志路径，远程排查能分清是哪个进程。

### 🔒 并发隔离
- CrispASR 核心与 ffmpeg 解压各持跨进程锁（并发解压会先删 `.exe/.dll`，等于删掉对方正在运行的 `crispasr.exe`）。
- 同一目标文件的下载串行，不会把对方的残档当续传起点。
- 同一份字幕两个实例只许一个写，后来者自动落到 `名称 (2).srt`。
- 原子写临时名改唯一（`mkstemp`）+ Windows `os.replace` 冲突短重试，「转完最后一步写盘失败」不再发生。

### 🧪 工程
- 新增 `instance_lock.py`（Windows `msvcrt` 字节锁／POSIX `flock`；持有者崩溃由内核释放）。
- 测试 151 → 165 例：跨进程锁、持有者被 kill 后自动释放、锁不可写 ≠ 已占用、产物唯一化、并发原子写、客户端断连探测。

### 升级说明
- 覆盖安装即可，`settings.json` 与模型目录沿用。
- 双开时仍可强制并行（选「仍要再开一个」）：输出、下载、日志已互相隔离，但 **GPU／显存仍会争用**，建议只开一个。
